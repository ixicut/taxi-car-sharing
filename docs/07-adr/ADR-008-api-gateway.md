# ADR-008. API Gateway (Kong) як єдина точка входу

- **Статус:** Accepted
- **Дата:** 2026-10-26

## Контекст

Клієнти (Passenger App, Driver App, Web Console) і партнери звертаються до восьми сервісів. Пік: 50 замовлень/с і тисячі WebSocket-з'єднань водіїв і пасажирів. Потрібні єдина автентифікація, обмеження частоти запитів і спільна політика безпеки.

## Рушії рішення

- ASR-02 — захист від флуду на `/trips` у пік (rate limiting)
- ASR-05 — централізована перевірка JWT; партнерський доступ за API-ключем
- ASR-01 — проксі WebSocket для потоку геопозицій
- NFR-13 — наскрізний `trace-id`
- NFR-12 — клієнти не повинні знати топологію сервісів

## Розглянуті альтернативи

1. **Без Gateway: клієнти викликають сервіси напряму.** Менше компонентів, але кожен сервіс повторює автентифікацію, rate limiting і CORS; клієнти знають топологію; кожен сервіс стає публічною поверхнею атаки.
2. **BFF для кожного клієнта (пасажир, водій, консоль).** Оптимізована агрегація, але три додаткові сервіси; потреби клієнтів поки схожі (обидва мобільні застосунки на Flutter).
3. **Лише ingress service mesh.** Маршрутизація і mTLS, але немає API-ключів партнерів, квот, трансформацій на рівні API.
4. **Єдиний API Gateway (Kong).** Обрано.

## Рішення

Єдиний **Kong API Gateway** (CT-04) як точка входу:
- перевірка JWT за JWKS Identity Service (ADR-006), ролі й scope для маршрутів;
- rate limiting: за користувачем і IP, суворіший ліміт для `POST /trips`;
- API-ключі для партнерів (таксопарки), окрема політика квот;
- проксі WebSocket (геопотік, позиція водія);
- генерація і проброс `trace-id`;
- маршрутизація за версією (`/v1`, `/v2`).

Gateway **не містить бізнес-логіки** і не агрегує відповідей. Окремі BFF не вводимо; повернемося до цього, якщо вимоги клієнтів розійдуться.

## Наслідки

**Позитивні:**
- Єдине місце політик безпеки й квот; сервіси простіші.
- Внутрішню топологію можна змінювати без змін клієнтів.
- Приймає й послаблює пікові сплески ще до сервісів.

**Негативні / ризики:**
- Єдина точка відмови: мінімум дві репліки, health-перевірки, автомасштабування.
- Додаткова затримка (одиниці мілісекунд) на кожен запит і на WebSocket-з'єднання.
- Спокуса додати в Gateway бізнес-логіку; заборонено правилом і код-рев'ю.
- Внутрішні виклики сервіс-сервіс (gRPC) обходять Gateway, тому їхня безпека потребує окремого захисту (mTLS) — розглядається в STRIDE.
