# RideHub — агрегатор таксі та каршерингу

Пакет архітектурної документації складної інформаційної системи. Командний проєкт з дисципліни «Проєктування складних інформаційних систем».

Система об'єднує в одному застосунку пропозиції кількох таксопарків і каршеринг-операторів: замовлення поїздки, пошук водія з урахуванням геолокації в реальному часі, розрахунок тарифу, оплата через зовнішнього платіжного провайдера, оренда авто за хвилини.

## Напрями теми

1. **Вимоги та моделювання** — стейкхолдери (пасажир, водій, диспетчерська служба, платіжний провайдер), use-case модель замовлення поїздки, доменна модель поїздок/тарифів/водіїв, діаграма компонентів.
2. **Архітектура та розподілена система** — вибір стилю з урахуванням геолокації в реальному часі та пікових навантажень, C4-модель, синхронні/асинхронні інтеграції з картографічним і платіжним сервісами, Saga «пошук водія → підтвердження → оплата».
3. **Якість, патерни та документування** — діаграма станів поїздки, STRIDE для автентифікації водія та обробки платежу, fitness functions, журнал ADR.

## Домовленості

### Ідентифікатори

Кожен елемент має ID, на який посилаються інші розділи. Без цього трасування не працюватиме.

| Префікс | Що позначає | Приклад |
|---|---|---|
| `ST-xx` | Стейкхолдер | ST-01 Пасажир |
| `US-xx` | User story (функціональна вимога) | US-03 |
| `NFR-xx` | Нефункціональна вимога | NFR-02 |
| `ASR-xx` | Архітектурно значуща вимога | ASR-01 |
| `UC-xx` | Варіант використання | UC-01 Замовити поїздку |
| `BC-xx` | Bounded context / компонент | BC-02 Matching |
| `ADR-NNN` | Архітектурне рішення | ADR-001 |
| `TH-xx` | Загроза STRIDE | TH-05 |
| `FF-xx` | Fitness function | FF-01 |

### Діаграми

- Діаграми пишемо на **PlantUML**, кожна в окремому файлі `diagrams/<розділ>-<назва>.puml`.
- Кожна діаграма підключає спільний стиль: `!include _style.puml`.
- Для C4 використовуємо [C4-PlantUML](https://github.com/plantuml-stdlib/C4-PlantUML) (`!include <C4/C4_Container>`).
- Зображення лежать у `diagrams/rendered/` з тією ж назвою файлу і вставлені в Markdown: `![](../diagrams/rendered/<назва>.png)`.

**Генерація зображень.** Скрипт рендерить усі діаграми за один запуск. Він використовує `scripts/plantuml.jar` (або шлях у `PLANTUML_JAR`) з Java 11+, а якщо його немає — Docker-образ `plantuml/plantuml`:

```powershell
./scripts/render-diagrams.ps1            # Windows, PNG
./scripts/render-diagrams.ps1 -Format svg
```

```sh
sh scripts/render-diagrams.sh            # Linux / macOS / Git Bash, PNG
```
